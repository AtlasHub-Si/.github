# AtlasHub Galaxy — portfolio baseline

**One intelligence. Multiple worlds. One connected ecosystem.**

| Domain | Authority | Direction |
|---|---|---|
| AtlasHub.SI | Institutional communications | Official global website |
| AtlasHub Galaxy | Navigation and cross-domain context | Public showcase; future role-aware access |
| AtlasBot | Personal conversations, assistants and routines | OpenMausBot validation candidate |
| AtlasHQ | Organizational objectives, tasks, assignments, budgets and approvals | Paperclip-based enterprise control plane |
| AtlasCortex | Governed persistent memory and knowledge | GBrain and scoped MCP integration |
| AtlasInfra | Providers, models, credentials, compute, gateway and reliability | Shared platform services |
| AtlasDesk | CRM and commercial records | Future integrated billing |
| AtlasClub | Community and learning | Future team distribution |
| AtlasWorkforce | Portable role, skill and team definitions | Shared catalog, not a runtime |

## Operating rules

- Each mission has one execution owner. Handoff from AtlasBot to AtlasHQ must preserve authorization and traceability.
- Galaxy links to systems of record; it must not duplicate them.
- Reuse shared identity, scoped context and runtime interfaces before introducing services.
- AtlasRooms and historical OpenBot work are frozen as independent product tracks. Reusable components may be reviewed; no archival or deletion is implied.
- No new independent harness or agent framework unless validated gaps require one.
- Concept visuals are not live dashboards. Product direction does not establish deployment, certification or production readiness.
- Prioritize functional gates over branding and distribution: self-hosting, Hermes/gateway, Cortex, isolation, approvals, durable state, mission handoff, portability and license compliance.
